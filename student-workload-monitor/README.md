# Student Monitor — Клієнтська частина (Frontend Module)

Індивідуальний STEM-проєкт з освітнього компонента **«Розробник фронтенду програмних систем»**.

**Виконала:** студентка 3 курсу групи ІПЗ-33 (ПГ 7) Худоба Валерія  
**Тема проєкту:** Розробка клієнтської частини вебсистеми моніторингу навчального навантаження студентів (*Student Workload Monitor*).

---

## 📌 Призначення модуля

Клієнтська частина призначена для автоматизації обліку навчального навантаження здобувачів вищої освіти, контролю дедлайнів та візуалізації прогнозованих ризиків перевантаження на найближчі 7 днів.

### Основний функціонал фронтенду:
* **Управління профілями студентів:** перемикання між студентами, створення нового профілю з валідацією даних (ПІБ, Email, академічна група), видалення профілю.
* **Облік навчальних дисциплін:** додавання предметів із зазначенням викладача та кредитів ECTS (1–30), перегляд та видалення записів.
* **Керування завданнями та дедлайнами:** створення завдань, оцінка трудовитрат у годинах (0.5–200 год.), зміна статусу на «Виконано», видалення та багатопараметрична фільтрація (за предметом і статусом).
* **Візуалізація прогнозу навантаження:** динамічне відображення рівня ризику (`Low`, `Medium`, `High`), сумарних очікуваних трудовитрат, кількості активних завдань і рекомендацій системи.

## 🛠 Стек технологій та інженерні рішення

* **React 18 (Hooks & JSX):** побудова інтерфейсу на базі функціональних компонентів та реактивного стану (`useState`, `useEffect`, `useMemo`, `useRef`).
* **HTML5 & CSS3:** семантична розмітка, адаптивні сітки на базі **CSS Grid** та **Flexbox**.
* **Fetch API (RESTful JSON):** асинхронна взаємодія з бекендом (`GET`, `POST`, `PATCH`, `DELETE`) з паралельним завантаженням даних (`Promise.all`) та розбором помилок формату `ProblemDetails`.
* **Захищеність (Security):**
  * Захист від XSS-атак завдяки автоматичному екрануванню даних у JSX.
  * Клієнтська валідація форм (обмеження довжини `maxLength`, перевірка числових діапазонів та форматів).
* **UX та стани інтерфейсу:** індикатори завантаження (`isLoading`), блокування кнопок під час відправки запитів (`isSubmitting` / `disabled`) для запобігання дублюванню даних, спливаючі сповіщення (`Toast` із `aria-live="polite"`).

## 📂 Структура файлів фронтенду

```text
├── index.html                  # Кореневий HTML-документ, підключення React 18 та стилів
├── style.css                   # Стилізація та адаптивна верстка (Grid / Flexbox)
├── app.js                      # Головний компонент App (координація станів та API-запитів)
├── tests.html                  # Модульні тести клієнтської логіки (Mocha + Chai)
└── js/
    ├── api.js                  # Утиліти HTTP-запитів (apiRequest) та форматування дат
    ├── HeaderAndStudentForm.js # Верхня панель навігації та форма створення студента
    ├── ForecastSection.js      # Картки аналітичного прогнозу навантаження на 7 днів
    ├── SubjectsPanel.js        # Панель керування навчальними дисциплінами
    └── AssignmentsPanel.js     # Панель фільтрації, створення та управління завданнями
```

## 🚀 Запуск проєкту

1. Відкрийте термінал **Git Bash** у кореневій директорії проєкту (де знаходиться `docker-compose.yml`).
2. Запустіть систему командою:
   ```bash
   docker compose up --build -d
   ```
3. Відкрийте вебдодаток у браузері (Google Chrome, Mozilla Firefox або Microsoft Edge) за локальною адресою контейнера (наприклад, `http://localhost:8080`).

## 🧪 Модульне тестування (Unit Tests)

Для перевірки клієнтської логіки (валідація годин трудовитрат, фільтрація списку завдань, генерація класів ризику) реалізовано набір тестів на базі **Mocha** та **Chai**.

* **Запуск:** відкрийте сторінку `/tests.html` у браузері при запущеному вебсервері (наприклад, `http://localhost:8080/tests.html`).
